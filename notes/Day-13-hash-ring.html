Day 13 补充图解 · Consistent Hashing

Hash 是怎么把空间“绕成一个环”的

两步：先搞懂 hash 把任意输入变成一个定长整数；再看“首尾相接的环”其实只是给这个整数空间套了一层模运算——和钟面是同一招。

一、Hash：把任意输入搅成一个定长整数

一句话：hash function 是一个确定性函数，把任意输入（任意长度的字符串、数字、字节）映射成一个固定大小的整数，落在 [0, 2³²−1] 这样的固定区间里。

它的四条性质，每条都有用途：

性质含义为什么重要
Deterministic同一输入永远得同一输出存得进、找得回——定位数据的前提
定长输出输出位数固定，与输入长度无关把无限的输入空间压进有限的输出空间
均匀 + avalanche输出近似均匀；输入改 1 bit，输出约一半 bit 翻转相似 key 也打散 → 分区均匀
必然碰撞不同输入可能撞到同一输出输入空间 ≫ 输出空间，由鸽笼原理必然发生；好 hash 让碰撞均匀分摊

“内部怎么做到”——就是一串算术 + 位运算的搅拌。给个玩具级例子（经典 DJB2）找回手感：

djb2.py — 把字符串搅成一个 32-bit 整数（原理示意）
def h(key):
    h = 5381
    for c in key:                 # 逐个字符
        h = h * 33 + ord(c)        # 乘一个数,再累加字符码 → 每个字符都参与
    return h % 2**32             # 截断成 32-bit → 落进 [0, 2³²−1]

真正生产用的 MurmurHash / xxHash 位运算更复杂（为了更强的 avalanche），但骨架就是这个：用算术把输入搅成一个定长整数。

一个区分点：crypto hash vs non-crypto hash
SHA-256 这类加密 hash 额外要求“不可逆、抗碰撞攻击”，所以慢；Murmur / xxHash 这类非加密 hash 只要“快 + 均匀”。分区和哈希表用的是后者——你不防黑客，只要打散得快又匀。

你“以前接触过”的大概率是这个场景——哈希表 / 字典：bucket = h(key) mod 桶数，O(1) 查找（Python dict、SQL hash join 都是它）。而 Day 13 文档说的朴素分区分配法 partition = h(key) mod N 是同一个套路——问题正出在这个 mod N 上：N 一变，全乱。下面就看环怎么救它。

二、“首尾相接成环” = 给整数空间套上模运算

“环”不是物理的圆，是一个数学结构：模运算（modular arithmetic）。32-bit hash 的输出本来是一条有限数轴 {0,1,…,2³²−1}；我们只是规定：走到顶 2³²−1 再 +1 就回到 0。把数轴两端粘起来，它就成了环。

(2³²−1) + 1 ≡ 0  (mod 2³²) 所有位置都活在 ℤ / 2³²ℤ 里：加法自动回绕（wrap around）

你一定熟这个结构——钟面就是模 12 的环：11 点 +1 = 12/0 点，再 +1 = 1 点。consistent hashing 的环，不过是一个刻度多到 2³² 的时钟。

把节点和 key 用同一个 hash、同一个值域都丢上这个环，“归属”就有了精确定义：

1

放上环。pos(node)=h(node_id) mod 2³²、pos(key)=h(key) mod 2³²——节点和 key 现在是同一把尺子上的点，可比较。

2

找 successor。key 落在 p，它归属所有节点位置中 ≥ p 的最小那个（顺时针遇到的第一个节点）。图里 k₁ → N2。

3

越界就回绕。若 p 比所有节点位置都大（落在接缝前），就绕回取最小的那个节点。图里 k₂ → N1。这一步就是“环”唯一真正用到的地方——没有它，k₂ 无家可归。

owner(p) = min{ sᵢ ∈ S : sᵢ ≥ p }  否则  s₁ S = 已排序的节点位置；实现上对 p 做 binary search 找 successor，越界 wrap 到第 0 个 · O(log n)

三、这样为什么“只搬 1/N”，mod N 却全搬

根本差别：环上加一个节点，只改“一段弧”的归属（局部）；mod N 改的是整个映射函数（全局）。

顺带补 virtual nodes 的数学动机：只把 n 个物理节点扔上环，弧段长短随机、可能很不均（某节点占一大段 → 倾斜）。于是每个物理节点放数百个虚拟点（h("shard-02#0")、h("shard-02#1")…），把它该占的弧切碎再均匀撒满全环——大数定律下每个物理节点占的总弧长趋近 1/N，负载就匀了。增删节点时，搬动的弧也由所有幸存节点平摊，而不是全压给某一个邻居。
一句话收尾
hash = “确定性地把任意输入搅成一个定长整数”；环 = “给这个定长整数空间套上模运算，让它超过上界就回绕”。两者一拼，consistent hashing 就成立了。
