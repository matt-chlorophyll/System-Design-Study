## 待深挖 / 存疑

> 还没想透、或想之后回头补的点。

- [ ] 思考题 1 接 Day 18：选主只保证「同一时刻多数派只认一个 leader」，但**假死的旧 coordinator 在租约过期前还能继续写**——这正是 idempotency / fencing token 要兜底的窗口。想清楚「选主」和「幂等」各防的是哪一段。
- [ ] 思考题 2：etcd 给的是**强一致 + 单调可线性化的读写**（谁是当前版本，全集群秒级一致），关系库给的是**事务 + 可审计的历史**。两者要的不是同一样东西——一个管「现在生效哪个」，一个管「历史可追溯」。
- [ ] 回看 Day 12（quorum / CAP / PACELC）：Raft 的「多数派必有交集」就是 quorum 防脑裂的算术基础；共识在 CAP 里是明确选 C 舍 A 的一类系统。
- [ ] **Fencing token**：租约过期后，光靠「停止续约」还不够，被保护的资源（如批处理写入）还得校验 token 递增，拒绝旧持有者的迟到写——这个机制今天没展开，值得单独补。
- [ ] Day 26（部署与编排）：Kubernetes 拿 etcd 当状态后端——今天学的「Raft + 租约 + 选主」就是 k8s 控制面可靠性的底座，到那天会再撞上。
